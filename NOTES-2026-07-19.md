## 1. GitHub / push projet Orion

### Création de dépôt
- Le push Orion peut créer un dépôt GitHub (avant : `new_repo` sans `create_repo` → 404).
- Dépôts créés **publics** par défaut (`private:true` si besoin).
- Action **« Rendre public sur GitHub »** (menu projet + `orion_project` / `git_commit` `make_public`).
- Si le dépôt existe déjà (HTTP 422) → réutilisation + passage éventuel en public.

### Liste des dépôts à chaque push
- Plus de création auto forcée à chaque commit.
- À chaque push : **liste des dépôts** (projet en tête, défaut, puis « Créer un nouveau dépôt… »).
- Même chemin de fichier = **remplace** le contenu existant sur GitHub (pas de doublon).

### Fix « Update ref HTTP 404 »
- PATCH sur `/git/refs/` (pluriel), plus `/git/ref/`.
- PATCH HTTP natif (ne plus forcer un POST nu que GitHub ignore).
- Fallback Contents API si la mise à jour de branche échoue.
- Messages d’erreur plus clairs (FR).

**Fichiers clés :** `OrionProjectTool.java`, `GitCommitTool.java`, `GitHubApiClient.java`, `OrionProjectView.java`

## 4. PromptCompiler (✨) — traducteur Yann → Orion

Pipeline :

```
Demande naturelle
      ↓
Analyse d’ambiguïté (GPT-OSS 120B)
      ↓
READY | RECOMMENDED | REQUIRED
      ↓
(Interprétation oui/corrige/fais au mieux) ou (max 2 questions)
      ↓
PromptCompiler → ResolvedTask → Mission
      ↓
Aperçu dans le champ → ↗ Orion
```

### Composants (`orion/prompt/`)
| Composant | Rôle |
|-----------|------|
| `YannGlossary` | Expressions (« regarde un peu », « refais », lag…) |
| `PromptAmbiguityAnalyzer` | Décide READY / RECOMMENDED / REQUIRED |
| `ClarificationManager` | Max 1 tour, gabarits conversationnels |
| `PromptCompiler` | Formate un `ResolvedTask` (n’invente rien) |
| `ResolvedTask` | Mission, contexte, objectif, actions, exclusions, validation, hypothèses |
| `PromptReadiness` | Enum à 3 états |

### Règles anti-interrogatoire
- Pas de questions systématiques.
- Max **2** questions, max **1** tour.
- Préférer *« Je comprends : … C’est bien ça ? »*.
- Toujours *« fais au mieux »*.
- Ne pas redemander ce qui est déjà connu (projet / préférences).

### UI Orion
- Bouton **✨** à côté de **↗**.
- Menu ⋮ → **Apprentissage code ON/OFF**.

**Fichiers clés :** `OrionPromptRewriter.java`, `PegaseSession.rewriteOrionPrompt`, `OrionStreamView.java`

## 5. Apprentissage code (candidats) — pas la mémoire chat

> **Important :** ce n’est **pas** la mémoire Pégase (`MemoryRepository` / souvenirs / tours de discussion).

| Système | Rôle | Touché aujourd’hui ? |
|---------|------|----------------------|
| `MemoryRepository` | Souvenirs chat, tours Discussion, injection contexte Pégase | **Non** |
| `VoiceIntentLearnStore` / `LearnModeStore` | Apprentissage voix / routage | **Non** |
| `learning/*` (LearningEngine, candidats routines) | Apprentissage routines / observations | **Non** |
| **`CodeLearnStore`** (nouveau) | Préférences **code** pour le PromptCompiler Orion | **Oui** |

### Routines — inchangées aujourd’hui

Le système routines / apprentissage V1 reste tel quel :

| Pièce | Rôle |
|-------|------|
| `RoutineSettingsActivity` | UI routines + section candidats d’apprentissage |
| `LearningEngine` | Détecteurs sur observations |
| `RoutineTimeDetector` | Propose un décalage d’horaire de routine |
| `IntentionPreferenceDetector` | Boost / suppress d’intentions |
| `LearningCandidateStore` + Oui/Non/Plus tard | Validation des candidats |
| `ObservationStore` | Traces pour les détecteurs |

**Aucun lien** pour l’instant avec le PromptCompiler Orion (`CodeLearnStore` ≠ candidats routines).

Pistes possibles plus tard :
- une mission Orion répétée → observation → candidat « préférence code » aussi côté routines/Situation ;
- ou exporter un candidat `CodeLearnStore` accepté vers `LearningCandidateStore`.

### Ce que fait `CodeLearnStore`
- Préférences **confirmées** (après « Je le retiens ? ») → réinjectées dans le méta-prompt ✨.
- **Candidats** proposés → dialogue Oui / Non (jamais écrit en silence).
- Q/R de clarification de session (legacy) pour demandes proches.
- Toggle : menu Orion ⋮ → *Apprentissage code ON/OFF*.

### Ce qui n’est pas encore branché
- Les missions / précisions Orion **n’écrivent pas** dans `MemoryRepository`.
- Pégase Discussion **ne lit pas** `CodeLearnStore` pour le chat général.
- Pas de synchro « souvenir permanent » du type *« Yann veut toujours l’orbe pour les particules »* hors PromptCompiler.

Piste naturelle ensuite : après confirmation d’un candidat code, optionnellement créer un souvenir `MemoryRepository` (source = `orion_code_learn`) pour que le chat Pégase le connaisse aussi.

## 6. QA automatique Orion (après Mission)

Pipeline silencieux après **↗** si le prompt est une Mission :

```
Orion génère
      ↓
OrionQaChecker
  • structurel (diff vs « Ne pas toucher » / hors scope CSS)
  • sémantique (GPT-OSS 120B : CONFORME / NON_CONFORME)
      ↓
NON_CONFORME → + contraintes → régénère (max 2)
      ↓
OK → « QA OK — tu peux push »
ou échec → « Voir le diff ? »
```

| Pièce | Rôle |
|-------|------|
| `orion/qa/OrionQaChecker.java` | Structure + sémantique |
| `orion/qa/OrionQaLoop.java` | Max 2 itérations |
| `orion/qa/OrionQaReport.java` | COMPLIANT / NON_COMPLIANT |
| `PegaseSession.completeOrionQaSync` | Juge LLM |

Toggle : menu Orion ⋮ → **QA auto ON/OFF** (ON par défaut).

## 7. Bureau — note technique pour Orion

Menu Bureau → **« Note technique (Orion) »** :
- Pégase (GPT-OSS 120B) reformate le MD ouvert en note technique.
- Sections : Objectif, Contexte technique, Fichiers, À faire (`- [ ]`), Ne pas toucher, Critères OK, Notes techniques.
- Compatible avec le PromptCompiler / Orion (moins de flou qu’un plan narratif).
- « Structurer le plan » reste le template planning (Objectifs / Décisions / Tâches…).

Squelette : `BureauPlanTemplate.technicalNote()`.

---

## 8. Comment l’utiliser (rappel)

1. Orion READY, projet actif.
2. Taper naturellement → **✨**.
3. Si interprétation → `oui` / `corrige : …` / `fais au mieux` → **✨** encore.
4. Relire la Mission → **↗** (QA auto en silence si conforme).
5. Push → choisir le dépôt dans la liste → confirmer dans Discussion.
